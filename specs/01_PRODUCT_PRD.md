# 01 · PRD — «Орбита», цифровой деканат будущего

> Статус: утверждено для прототипа · Владелец: Backend & Security · Связанные документы: `02_DESIGN_SYSTEM.md` (UI), `03_DATA_AND_SECURITY.md` (данные и безопасность), `04_API_CONTRACT.md` (API).
>
> Все персональные данные в прототипе вымышленные. Совпадения с реальными людьми случайны.

## 1. Проблема и цель

Студент тратит время на поиск информации, разбросанной по LMS, бумажным приказам, чатам старост и окошку деканата: где пара, сколько баллов не хватает до допуска, когда дедлайн, сколько ждать справку. Сотрудник деканата тонет в однотипных заявках и не может быстро оповестить группу о переносе.

**Цель прототипа** — одно веб-приложение, которое:

1. показывает студенту «фокус дня»: ближайшую пару, горящие дедлайны, статус заявок, средний балл;
2. делает БРС прозрачной: из чего складывается балл и сколько не хватает до порога;
3. превращает справки в онлайн-заявки с реестровым номером и статусом;
4. даёт деканату очередь заявок и инструмент массового оповещения;
5. отвечает на вопросы студента ИИ-ассистентом, который знает **его** баллы и дедлайны.

## 3. Функциональные модули

### 3.1. Вход и сессия

- Вход по email + пароль. Ошибка всегда обобщённая: «Неверный email или пароль» (не раскрываем, существует ли аккаунт).
- Сессия — 8 часов, хранится в HttpOnly-cookie. Выход удаляет cookie.
- После 5 неудачных попыток за 15 минут вход для пары «IP + email» блокируется с ответом `429`.

### 3.2. Фокус дня (дашборд)

Для студента:

- **Ближайшая пара** — следующее занятие группы по московскому времени (сегодня позже текущего момента, иначе первое занятие ближайшего учебного дня). Если пара перенесена — бейдж «Перенос» и старая аудитория.
- **Горящие дедлайны** — задания в статусе `TODO`/`OVERDUE`, отсортированные по сроку; «горящий» — срок ≤ 72 часа или уже просрочен.
- **Активные заявки** — в статусах `NEW` и `IN_REVIEW`.
- **Средний балл БРС** — среднее `currentTotal` по всем дисциплинам, округление до 0,1.
- **Непрочитанные уведомления** — счётчик.

Для сотрудника деканата — статистика заявок: всего, по статусам, новых за сутки, число студентов и последние 5 заявок.

### 3.3. Расписание

- Неделя Пн–Сб (`dayOfWeek` 1–6), пары с временем, типом (Лекция / Практика / Лабораторная), корпусом, аудиторией и преподавателем.
- Перенесённое занятие (`isRescheduled = true`) показывает старую аудиторию `oldRoom`.
- Студент видит только свою группу; деканат — все группы.

### 3.4. БРС — балльно-рейтинговая система (0–100)

Семестровый рейтинг по дисциплине — сумма трёх составляющих:

| Составляющая | Поле | Типичный максимум |
|--------------|------|-------------------|
| Лабораторные / практические работы | `labsScore` / `labsMax` | 40 |
| Рубежный контроль (РК) | `midtermScore` / `midtermMax` | 40 |
| Посещаемость и активность | `attendanceScore` / `attendanceMax` | 20 |
| **Итого семестр** | `currentTotal` | **100** |

`examMax` — вес промежуточной аттестации (экзамен/зачёт) в итоговой оценке. Итог по дисциплине:

```
итог = round( currentTotal × (100 − examMax) / 100 + examScore ),   examScore ∈ [0; examMax]
```

Пороги (единые для бэкенда, ИИ-ассистента и UI):

| Порог | Значение | Смысл |
|-------|----------|-------|
| Допуск к аттестации | `currentTotal ≥ 50` | ниже — **риск недопуска**, дисциплина помечается `hasDebt` |
| Удовлетворительно | 60–70 | «3»; для зачёта — «зачтено» |
| Хорошо | 71–84 | «4» |
| Отлично | 85–100 | «5»; для зачёта ≥ 60 возможен «автомат» |
| Условие повышенной стипендии (ПГАС, рейтинговая часть) | все дисциплины ≥ 85, нет долгов | |

API отдаёт для каждой дисциплины вычисленные поля: `hasDebt`, `pointsToAdmission` (сколько не хватает до 50), `pointsToExcellent` (до 85), `grade` («Отлично»/…).

**Статус стипендии** (`scholarshipStatus`) хранится у пользователя строкой, например «Академическая повышенная (ПГАС — на рассмотрении)» или «Не назначается: обучение по договору».

### 3.5. Трекер ДЗ и дедлайнов

- Задание: дисциплина, название, описание, дедлайн (ISO-8601), вес в баллах БРС (`brsWeight`), статус.
- Жизненный цикл: `TODO → SUBMITTED → GRADED`; `TODO → OVERDUE`, если дедлайн прошёл (статус пересчитывается сервером при каждом чтении).
- Сдача: ссылка на работу (только `https://`) + необязательный комментарий. Разрешена из `TODO`, `OVERDUE` (поздняя сдача, преподаватель решает о штрафе) и повторно из `SUBMITTED` (замена ссылки). Из `GRADED` — запрещена (`409`).
- Сдать можно только своё задание (`403` при попытке сдать чужое).

### 3.6. Учебные материалы

- Привязаны к факультету: студент видит материалы только своего факультета.
- Категории: Конспект · Шпаргалка к РК · Билеты · Шаблон лабы. У материала — время чтения и полноценный текст в Markdown (3–5 абзацев с формулами и примерами).
- Из материала можно открыть ИИ-тьютора с контекстом этого материала (`contextTitle`).

### 3.7. Справки и заявки

| Код типа | Название |
|----------|----------|
| `STUDY_CERTIFICATE` | Справка об обучении |
| `MILITARY_CERTIFICATE` | Справка для военкомата |
| `FINANCIAL_AID` | Заявление на материальную помощь |
| `RETAKE` | Направление на пересдачу |
| `PGAS` | Заявка на повышенную государственную академическую стипендию (ПГАС) |

- Жизненный цикл: `NEW → IN_REVIEW → APPROVED | REJECTED`. Перевести может только деканат; при каждой смене статуса владельцу приходит уведомление категории `REQUEST`.
- При создании присваивается **реестровый номер** вида `ОРБ-2026-0418` (год + порядковый номер, уникален).
- Отказ требует комментария деканата (`adminComment`), чтобы студент понимал причину.
- Одновременно у студента не может быть двух активных (`NEW`/`IN_REVIEW`) заявок одного типа — `409`.

### 3.8. Уведомления и объявления

- Категории: `DEADLINE`, `SCHEDULE` (перенос/изменение пары), `REQUEST` (статус заявки), `DEAN` (объявление деканата, в т.ч. критическое).
- Деканат рассылает объявление всем студентам или одной группе. Если указаны дисциплина и новая аудитория — у занятий этой дисциплины в целевой группе меняется аудитория (`oldRoom` ← прежняя, `isRescheduled = true`), уведомление уходит с категорией `SCHEDULE`.
- Студент может отметить все уведомления прочитанными.

### 3.9. ИИ-ассистент «Орбита Copilot»

Два режима:

| Режим | Назначение | Источник данных |
|-------|------------|-----------------|
| `tutor` (UI: `TUTOR`) | Объясняет тему, помогает с ДЗ, строит план подготовки к РК | Материалы факультета (по `contextTitle`), задания студента |
| `concierge` (UI: `DEANERY`) | Отвечает на вопросы о баллах, стипендии, дедлайнах, справках, регламентах | БРС, задания, заявки, расписание студента и регламенты из §3.4–3.7 |

- Перед ответом сервер собирает **персональный контекст** из БД текущего пользователя (идентичность — только из сессии).
- Если задан `AI_API_KEY` — серверный запрос к OpenAI-совместимому LLM (`AI_BASE_URL`, `AI_MODEL`); ключ никогда не попадает на клиент.
- Если ключа нет или LLM недоступен — детерминированный генератор строит структурированный персональный ответ на основе реальных баллов, дедлайнов и регламентов. Жюри может тестировать чат без внешних ключей.
- Ответ: `{ reply, suggestions[], source: 'llm' | 'rules' }`. Лимит — 20 запросов в минуту на пользователя (`429`).
- Ассистент не выдумывает данные: если информации нет, так и говорит и предлагает обратиться в деканат.

## 4. Нефункциональные требования

- **Автономность**: SQLite-файл, без внешних сервисов и VPN. Изменения жюри сохраняются сразу.
- **Безопасность**: защита от IDOR на каждом ресурсе, bcrypt, JWT в HttpOnly-cookie, секреты только в `process.env` (см. `03`).
- **Производительность**: ответы API < 300 мс на демо-данных.
- **Язык**: интерфейс и сообщения об ошибках — на русском.

## 5. Демо-сценарии для жюри

1. **Отличник**: войти → увидеть дедлайн через ~14 ч и перенос аудитории → открыть БРС (88–94) → спросить Copilot «хватает ли мне на ПГАС?» → заказать справку для военкомата.
2. **Зона риска**: войти → критическое уведомление деканата → БРС: дисциплина с 42 баллами и «не хватает 8 до допуска» → просроченное ДЗ, сдать с опозданием → Copilot «как избежать недопуска?».
3. **Деканат**: войти → очередь заявок → одобрить пересдачу Марии с комментарием → разослать перенос аудитории группе М3203 → войти Алексеем и увидеть уведомление и новую аудиторию.
4. **IDOR**: под студентом открыть `/api/requests/<id чужой заявки>` → `403` с сообщением о защите.
